# 小厨房 · Kitchen Inventory

供单人使用的厨房库存 Web App。简体中文界面，无登录、无后端，所有数据仅保存在当前浏览器的 localStorage。

## 运行

需要 Node.js 20.19+ 或 22.12+。在项目根目录执行：

```sh
pnpm install
pnpm dev
pnpm build
pnpm test
pnpm typecheck
pnpm preview
```

也可使用 npm install / npm run dev / npm run build / npm test。首次安装需要联网。依赖已安装时，不依赖包管理器的启动方式：

```sh
node node_modules/vite/bin/vite.js --host 127.0.0.1
```

开发地址通常为 http://127.0.0.1:5173/，以终端打印地址为准。手机联调可执行 `pnpm dev --host 0.0.0.0`，在同一局域网使用电脑 IP 打开。不同地址、端口和浏览器拥有独立库存，需要通过 JSON 迁移。

## 功能

- 库存新增、编辑、删除；中英文/德文名称；备注、单位、类别、位置和可选保质期。
- 搜索名称与备注，按类别、存储位置、状态筛选。
- 一次点击增减 1；数量变化弹窗支持任意消耗或补充；消耗不允许超过现有数量；标记用完、确认有货。
- 未知数量使用 `null`，不会被强制改成 1。有货统计只计算 `available` 状态。
- 保质期 3 天内及已到期提醒，未填写日期不推测。
- 独立购物清单，手动添加、修改计划数量及单位、勾选购买、批量入库。
- 同名称（忽略大小写）且同单位的采购合并；不同单位分开记录。原库存或采购数量未知时保留未知，待核实的原数量不参与求和；已用完的库存按新采购量补充。
- 类别新增、重命名、删除；删除类别将记录移到“其他”。
- JSON 导出、严格校验导入并确认替换、重置示例数据前二次确认。
- 首次无数据才创建 8 项确认库存和 16 项待核实历史记录，刷新不会覆盖。损坏的数据不会自动重置，可下载原始数据恢复。
- 响应式列表、空状态、操作提示、图标按钮无障碍名称、原生弹窗键盘操作。

## 验证

已通过 TypeScript 与生产构建。28 项自动测试覆盖原有库存逻辑及 Phase 2 的解析、事务、别名、单位、迁移、持久化和撤销。

浏览器实测：新增 10 个测试鸡蛋并刷新、消耗到 8、标记用完后退出有货计数、从购物清单采购 6 个再入库、未知数量香肠保存、JSON 导出并重新导入。测试记录已清理。390px 和 320px 视口未出现横向溢出；检查时无浏览器控制台错误。

## Phase 2：自然语言快速记账

首页“快速记一笔”输入中文，Enter 预览、Shift + Enter 换行。解析只生成建议，不改库存；确认后整批写入。预览支持修改名称/操作/数量/单位、选择匹配食材、排除单条、取消。错误项目默认不提交，未执行原文保留供修改。

示例（执行结果以预览中的当前库存为准）：

| 输入                         | 结果                                        |
| ---------------------------- | ------------------------------------------- |
| 买了10个鸡蛋                 | 当前 10 个 → 20 个                          |
| 吃了2个鸡蛋                  | 当前 10 个 → 8 个                           |
| 还剩3个鸡蛋                  | 将总量设为 3 个                             |
| 买了1kg肉末                  | 向现有 g 库存增加 1000g                     |
| 用了半包意面                 | 扣减 0.5 包；只在当前已知且单位兼容时可执行 |
| 买了两个洋葱和一盒牛奶       | 拆分两项增加操作                            |
| 肉末还有250g，广式香肠用完了 | 修正肉末总量，同时将香肠标记用完            |

原示例中的鸡蛋待核实、肉末以“份”记账，所以直接“买了鸡蛋”或“用了200g肉末”会要求盘点，不能把未知余量当作零。可在预览中改为“修正总量”，填写实际剩余数量，再确认。

新增模块：

```text
src/lib/
  inventoryTypes.ts          结构化操作、历史、解析器接口
  naturalLanguageParser.ts   本地规则解析；不写库存
  aliases.ts                 精确名称、显式别名、保守归一化匹配
  units.ts                   kg/g、L/ml 换算；不猜包装重量
  inventoryTransactions.ts   顺序预演、批量执行、统一历史与撤销
  storage.ts                 库存和历史一次写入；陈旧标签页检查
  naturalLanguage.test.ts    Phase 2 自动测试
src/components/
  QuickEntry.tsx             输入与逐条确认预览
  InventoryHistory.tsx       最近历史与撤销确认
  AliasSettings.tsx          自定义别名管理
```

数据格式升级到 v2，继续使用 `little-kitchen.v1` 存储键：读取 v1 时仅添加空历史和别名，下次成功保存再写 v2。v1 备份仍可导入；v2 备份包含历史和别名。没有重新初始化或覆盖用户库存。

所有普通库存操作仍走 `useKitchen.commit`，在这里统一生成历史；自然语言增减复用 `adjust`。最近 30 批记录保留时间、原文、每项操作前后数据和完整库存快照。只能撤销最近一批，撤销前检查库存及类别是否仍匹配操作后快照；撤销后标记已撤销，不递归撤销更早历史。购物清单独立保存，撤销库存不会重新生成已购商品。

支持阿拉伯数字、小数、常用精确中文数字与“半”，个/只/根/包/袋/盒/瓶/份/g/kg/ml/L；标点分句，“和、以及、顿号”连接同动作商品。支持主语前置盘点，以及“家里没洋葱了”。默认别名包括蛋、西红柿、Tomatenmark、Parmesan、香肠及肉末候选；多个候选必须人工选择。设置页面可添加/移除自己的别名。

不支持跨句指代（“它、剩下那些”）、复杂上下文、条件/计划/否定叙述、近似数量（三四个、大概半袋）和没有数量单位的购买记录；不支持包装重量换算。不可靠输入会提示改写。未来可通过 `InventoryParser` 接口接入服务端 LLM，仍必须经过同一预演、校验和确认流程，前端不存 API Key。

Phase 2 浏览器验收已覆盖：6 项混合批量预览与执行、逐条修改、取消、刷新持久化、完整撤销、v2 JSON 导入导出保留历史，以及 320px/390px 窄屏。验收库存已撤销恢复；历史中保留一条已撤销的验收批次。

## 后续扩展接口
